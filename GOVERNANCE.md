# OpenAction governance — bootstrap phase

OpenAction is currently maintainer-led but designed to become multi-stakeholder.

## Decision process
1. Open an issue describing the interoperability problem, real examples and why Core cannot already express it.
2. Prefer profiles/adapters before adding Core fields.
3. Breaking Core proposals require an RFC, test vectors and migration notes.
4. Record accepted/rejected decisions publicly.

## v1.0 graduation
Before `1.0.0`, invite at least one independent technical maintainer/reviewer and domain reviewers from at least three domains. No single vendor, model provider, authority or OpenAction-hosted cloud may be required to implement the protocol.

## Values
Human accountability for consequential decisions · minimum necessary data · portable evidence and approvals · explicit uncertainty · domain standards stay authoritative · publish failures, not only wins.
